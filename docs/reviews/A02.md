## 0) 一句话定位

**Lexilux** 是一个设计精良、生产就绪的 Python LLM API 统一客户端库，提供 Chat/Embed/Rerank/Tokenizer 四种 API 的函数式调用接口，当前成熟度约为 **Beta/生产可用阶段**，核心架构稳定但仍有优化空间。

## 1) TL;DR 总结 (10条)

### 总体健康度
- **代码质量**: 8/10 - 架构清晰、类型注解完整、文档详尽
- **测试覆盖**: 7/10 - 测试结构良好但覆盖率目标(68%)偏低
- **可维护性**: 8/10 - 模块分离清晰、设计模式合理
- **生产就绪度**: 7.5/10 - 核心功能稳定，缺少部分企业级特性

### 主要优点
1. **统一的函数式API设计** - `chat("hi")` 式调用简洁直观
2. **完整的异步支持** - 同步/异步双API设计
3. **健壮的错误处理** - 完整的异常层次和重试机制
4. **OpenAI兼容性强** - 支持多种提供商
5. **连接池优化** - HTTP连接复用提升性能

### 最大风险/技术债 Top 3
1. **P0 - 测试覆盖率不足** - 68%目标偏低，关键路径缺少边界测试
2. **P1 - 缺少性能测试** - 无压力测试、无并发验证
3. **P1 - 缺少分布式追踪** - 大型部署难以调试

### 建议立刻做的 Top 3
1. **提升测试覆盖率至85%+** - 尤其是异常流程和边界条件
2. **添加结构化日志** - 集成 OpenTelemetry 或 structlog
3. **完善性能基准测试** - 建立性能回归检测

### 最容易被忽略但影响很大的点
**连接池未正确关闭**: `_base.py:414` 显示 `response.close()` 但调用方可能遗漏，特别是streaming场景下连接泄漏风险高。

│   │   ├── history.py         # 会话历史管理
│   │   ├── tools.py           # Function/Tool调用
│   │   └── exceptions.py      # Chat专用异常

│   │   ├── registry.py        # 注册表实现 (553行) ⭐核心
│   │   ├── models.py          # 模型规格定义
│   │   └── factory.py         # 工厂模式
│   └── data/

├── tests/                     # 测试套件 (约35个文件)
│   ├── conftest.py            # pytest配置
│   ├── test_base.py           # 基础客户端测试
│   ├── test_chat*.py          # Chat相关测试 (10+文件)
│   └── test_*.py              # 其他功能测试
├── examples/                  # 示例代码 (14个文件)
├── docs/                      # 文档
└── benchmarks/                # 性能基准
```

**核心模块边界**:
- `_base.py`: HTTP层 + 连接池 + 重试
- `chat/`: 业务逻辑层
- `exceptions.py`: 跨模块异常统一
- `usage.py`: 统一结果格式

### 关键执行路径

```
用户API调用
    ↓
Chat.__call__() / Chat.stream()
    ↓
_build_payload() → 构建请求体
    ↓
BaseAPIClient._make_request()
    ├─→ tenacity重试装饰器
    ├─→ _do_request()
    │   ├─→ Session.post() (连接池)
    │   └─→ _handle_response_error()
    └─→ parse_chat_completion_response()
    ↓
返回 ChatResult / StreamingIterator
```

**外部依赖**:
- **HTTP**: `requests` (同步) + `httpx` (异步)
- **重试**: `tenacity` (指数退避)
- **类型**: `typing_extensions`
- **可选**: `transformers` (tokenizer)

### 构建/运行/部署链路
```
开发环境
├─→ uv sync --all-extras      # 快速依赖安装
├─→ make test                  # pytest运行
├─→ make lint                  # ruff检查
└─→ make format                # 代码格式化

发布流程
├─→ python -m build            # 构建wheel
├─→ twine upload               # PyPI发布
└─→ docs/make html             # 文档构建
```

from functools import lru_cache

@lru_cache(maxsize=128)
def _get_model_spec_cached(model_id: str) -> ModelSpec:
    ...
```
